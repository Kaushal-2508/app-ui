## Verdict

The eight auditors swept src/pages exhaustively (~130 page files) but only sampled src/components (~90 of ~700 .tsx files, roughly 15%). The page-level picture they give is trustworthy; the component-level picture is a sample, and the two largest folders in the repo (olympiad, 83 files; command-center, 58 files) were each represented by two files. Their central claim survives verification and is the right one: three shared primitives (MobileSheet bottom placement, FilterChip, FilterSheet trigger) hard-code a literal white ground that never flips, and that single dozen lines of CSS is what makes most of the portal unreadable in dark mode. Everything else is downstream of it or is the error-as-empty defect class, which I sized at 292 destructure sites across ~100 files with no error handling at all and 102 files carrying hand-rolled error blocks, because no ErrorState primitive exists. Two of their highest-severity claims do not survive a file open: the "Recharts collapses to zero height" finding on the three analytics detail pages (h-64 is a resolved 256px; the container is fine) and the "HeroCard banner violates the design system" finding on BadgeLeaderboardPage (it imports the achievements HeroCard, a different and sanctioned component, not the banned shared one). I also found one live, routed page nobody opened at all: src/pages/EvaluateAttemptPage.tsx, the teacher grading surface, which has no PageShell and drops its query error. The work should start with 12 lines in three primitive files, not with page migrations.

### Batch 5: Theme boot script, the remaining color maps, and the touch-affordance pass  (effort: medium)

Three cheap systemic fixes plus the long tail. First the theme boot: I confirmed index.html contains no theme script at all, and .dark is applied only by a useEffect in AppLayout.tsx:176 that waits on an async user_preferences query with staleTime Infinity. Every dark-mode user therefore gets at least one painted light frame per full load, the eight public routes never run the effect because AppLayout sits behind ProtectedRoute, and the `if (themePrefs?.theme)` guard means a null result leaves the previous user's class in place. ## Worst screens

- Dark mode, any screen that opens a bottom sheet (most of the portal). src/components/shared/sheets/MobileSheet.tsx:99 paints the default bottom placement bg-white while its own header at line 159 renders text-ink-900, which .dark redefines to 0 0% 96% (src/index.css:391). White title on a white panel. Nothing in index.css overrides .bg-white under .dark, verified by grep. 53-60 of 75 call sites pass no placement prop, so they all get it. Paired with FilterChip and the FilterSheet trigger (bg-white/85 + text-ink-700, where --ink-700 is 220 12% 80% in dark), the filter row and the sheet chrome of Exams, Homework, Teachers, Students and Syllabus are illegible at roughly 1.2:1. This is not off-palette, it is unreadable, and it is the first thing any dark-mode user hits.

The only admin surface with no PageShell anywhere in the chain, so it sits flat on bg-background while every sibling page floats on .surface-gradient, and it spans edge to edge on a wide monitor where everything else is capped at max-w-7xl. On top of that: five deprecated GradientKPICards in saturated blue/indigo/purple/red/emerald, a six-trigger shadcn TabsList (line 279) with no overflow-x inside AppLayout's overflow-x-clip column (AppLayout.tsx:235, main p-3 at line 382), so Subjects and AI Suggestions are unreachable on a phone, and an error branch that tells an admin to 'Select an institution' they already selected. It reads as a different product.

- /school/fees (src/pages/school/FeesManagementPage.tsx). This is a visible rendering fault rather than a style deviation, and it is the clearest signal that nobody has opened this area in a long time (its eight fees/ panel components were never audited either).

## Claims that did NOT survive verification

Do not re-open these on the next sweep.

- REFUTED - 'Recharts blocks on the three analytics detail pages sit in the exact configuration documented to collapse to zero height on mobile and stop rendering bars' (claimed at src/pages/school/ClassDetailPage.tsx:76 and repeated for SubjectDetailPage and TeacherDetailPage, 12 call sites). I opened ClassDetailPage.tsx:76: it is `<div className="h-64"><ResponsiveContainer width="100%" height="100%">`. h-64 is a resolved 256px, so height="100%" resolves against a real number; neither the parent Card's overflow-hidden nor md:grid-cols-2 changes that. The cross-cutting a11y auditor independently checked all 38 ResponsiveContainer sites and reached the opposite conclusion, and that one is correct. Do not budget work here.

- OVERSTATED - 'BadgeLeaderboardPage uses HeroCard as a page-spanning top banner, which the design system explicitly bans (checklist item 14)'. The import at src/pages/BadgeLeaderboardPage.tsx:30 is `@/components/achievements/HeroCard`, not `@/components/shared/surfaces/HeroCard`. They are two different components sharing a name - a fact a DIFFERENT auditor correctly reported. The banned one is the shared primitive; the achievements one is the sanctioned achievements banner used by AchievementsHero, PlayerCard and TeacherHero, and it defines its colors in .hero-card--* classes in both themes. Acting on this finding would mean rewriting a compliant component. The page's other three defects (no PageShell, the podium grid, the dropped error) all survive.

- ALREADY REFUTED BY AN AUDITOR, AND I CONFIRMED IT - the '113 unwrapped <Table>' grep signal. src/components/ui/table.tsx:7 wraps every table in `<div className="relative w-full overflow-auto rounded-2xl">`. Recording it so the number does not re-enter the plan on the next sweep.

- REFUTED AS A WORK ITEM - my own hypothesis that the big unaudited folders (attendance, command-center, syllabus) would be dark-mode debt pockets. I grepped them: command-center's 42 raw-palette lines are almost entirely saturated bg-emerald-500/bg-amber-500/bg-rose-500 RAG dots and progress fills that read correctly in both themes, syllabus's 23 are almost all /10 alpha tints, and attendance's 15 are mostly /10 and /90. Real defects across all three: roughly six lines, and the worst of them (SyllabusCoverageWidget's bg-slate-100 track) was already found. Do not commission a color pass for these folders.

- PARTIALLY REFRAMED - 'EmptyState's reason="error" prop is dead'. Confirmed literally true (declared in EmptyStateProps at line 20, never destructured in the component body at lines 33-41, no retry affordance). But the fix is not to revive the prop - an error state needs different copy, a different tone and a Try again button, which is a separate primitive. The auditor's own conclusion (build ErrorState) is right; anyone reading the finding as 'wire up the prop' would ship a worse fix.
