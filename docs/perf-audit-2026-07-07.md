# Load & Request-Storm Audit — 2026-07-07

Full-codebase QA/QC sweep for **request amplification** (clients hammering REST/edge functions) and **peak-load DB freeze** risk at the 3–5K-concurrent-user target (CLAUDE.md §23). 683 files scanned by 15 slice auditors; 192 deduped findings. The highest-impact items were fixed the same day (status ✅ below); everything else is the working backlog, ordered hot-path-first within each severity.

**Fixed this pass (see branch diff of 2026-07-07):**
1. **Exam answer-key leak (P0 security)** — `exam_questions(*)` shipped `options[].isCorrect` + `correct_answer` + `explanation` to students during live exams. New sanitized `get_exam_paper` RPC (migration `20260707130000`, whitelist `{id,text}` per option, **applied to prod + verified over 5,000 real options**) now serves the attempt page. RLS tightening staged in `20260707131000` — **apply only after this frontend deploys** (sequencing note in the file). **Corrected 2026-07-08:** live prod has THREE permissive SELECT policies (RLS ORs them); the first cut only tightened `View exam questions` and left the WIDER `Users can view exam_questions` (institution-wide read, no class/attempt check) fully open. The migration now drops BOTH. Dry-run in a rolled-back prod transaction confirmed it parses, helpers resolve, and SELECT policies collapse 3→2.
2. **Submit thundering herd (P0)** — `useExamAttempt` re-saved EVERY answer at submit (~100 RPCs/student; 200–300K RPC burst at an exam-window close). Now saves only still-dirty answers; failed autosaves are re-queued instead of silently dropped; manual submit blocks (retryable) if final saves fail, timer auto-submit stays best-effort.
3. **profiles request storm (P0)** — `useAuth` (56 files, 5–10 instances/page) fired a `profiles` SELECT per mounted instance per navigation and per auth event. Module-level 5-min cache + single-flight dedupe; cleared on sign-out.
4. **Unbounded `final_results` read (P0)** — `useStudentPublishedResults` fetched ALL published results (1000-row cap) and filtered client-side; now server-filtered by student + `.limit(200)`.
5. **Per-keystroke query chain (P0)** — study-materials search re-ran a ~10-query resolution chain per keystroke; list is now fetched once (bounded 100, explicit columns) and searched client-side.
6. **Per-navigation profile fetch (P1)** — `GuidedTourProvider` (mounted in AppLayout) refetched `onboarding_completed` on every route change; now a `staleTime: Infinity` query updated via `setQueryData` on completion.
7. **Notification polling halved (P1)** — bell list no longer polls every 60s for every user (realtime + fetch-on-open, explicit columns); unread badge stays on a 60s head-count poll as the realtime fallback.
8. **Badge/stat counts server-side (P1)** — `useAutoBadgeAward` (runs on every login + submit) and `useStudentStats` row-pull `.length` counts → HEAD counts via new `src/lib/headCount.ts` (also removed raw `fetch()`+`(supabase as any)` calls and a stray RPC call).
9. **Edge-function hygiene (P1)** — `AbortSignal.timeout` on all LLM calls (`_shared/aiProvider.ts` 60s, `auto-grade-submission` 30s, `generate-exam-insights` 30s) and Razorpay (10s, 504 on timeout) + validate-before-IO on public `oly-payment-create-order`. **Not yet deployed** — deploy with:
   `npx supabase@latest functions deploy <fn> --project-ref gyymkgohcijeksmrzuyw` for `auto-grade-submission`, `generate-exam-insights`, `oly-payment-create-order`, and every fn importing `_shared/aiProvider.ts` (`generate-questions`).
10. **Client edge-invoke timeout (P1)** — `invokeEdgeFunction` fetches now carry a 30s `AbortSignal.timeout`.
11. **Exam-telemetry flush (P1, partial)** — sequential per-question upserts → bounded parallel chunks; a `record_question_telemetry` RPC (single request + atomic increments) is flagged as PERF-DEBT in the file.

**Verification:** `npm run typecheck` clean · `npx eslint` on all touched files introduces zero new errors (19 pre-existing `any`s in those files remain, listed below) · `npx vite build` exit 0 · RPC auth-gate + sanitization verified against prod data.

**Notes for the backlog below:** only ~15 findings got adversarial verification before the session cap; treat unverified entries as auditor-reported, confirm before large refactors. Three audit slices died on the session cap and were NOT swept: `src/components` dirs f–o and a–e (partially), and edge functions h–z (non-oly) — schedule a follow-up sweep for those.
