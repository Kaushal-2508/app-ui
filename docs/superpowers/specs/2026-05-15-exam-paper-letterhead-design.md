# Exam Paper Letterhead — Design Spec

**Status:** approved (user: tushar)
**Date:** 2026-05-15
**Branch:** `main` (single PR, additive)

## Goal

Every surface that shows an exam as a printable / downloadable paper renders with the **institute's own letterhead** at the top — logo + school name + (optional) address line + thin teal accent rule. Replace the bulky 3×2 grey meta-tile grid with a single meta-strip line. Footer no longer says *"Generated by SALCI Assessment Platform"* (brand bleed onto the school's paper).

The literal user ask: *"add the logo in the exam papers, give the users a better UI/UX, wherever the exam appears in PDF form the logo should be there."*

## Surfaces in scope

Question paper renders (Tier 1, the user's literal ask):

| File | Today | After |
|---|---|---|
| `src/components/exam/ExamPreviewDialog.tsx` | inline HTML in `handlePrint`; preview is its own React render | preview uses shared `<ExamPaperDocument>`; print uses shared `printExamPaper` |
| `src/components/exam/ExamPreviewPrint.tsx` | inline HTML in `handlePrint`; preview is its own React render | same as above |
| `src/components/exam/DownloadQuestionPaperButton.tsx` | inline HTML preview, `html2pdf.js` download, inline HTML print | shared preview + shared printer + `html2pdf` over the shared rendered DOM |
| `src/components/exam/OfflinePublishDialog.tsx` | same shape as DownloadQuestionPaperButton | same |

Results PDF renders (Tier 2, "wherever exam appears in PDF"):

| File | Today | After |
|---|---|---|
| `src/components/exam-results/ExamReportPDF.tsx` | `html2pdf` over an HTML template with a plain centered title | prepend the shared letterhead HTML; otherwise unchanged |
| `src/components/exam-results/StudentReportPDF.tsx` | same | same |

Out of scope: timetable print, fee/salary receipts, CBSE reports utility, exam-taking student UI, exam-creation flow itself.

## Header design — Option B (chosen)

```
+---------------------------------------------------------+
|  [LOGO]    DELHI PUBLIC SCHOOL R.K. PURAM                |
|            Sector 12, R.K. Puram, New Delhi · +91-...    |
|---------------------------------------------------------|
|  Class 10A · Mathematics · Term 1 Exam · 2026-05-20      |
|  Duration 90 min · Total Marks 80 · Pass 33%             |
+---------------------------------------------------------+
                Title of the Exam Paper
                  (description line)
```

- Logo on the left, max 56 px tall (preview) / ~16 mm (print). Aspect preserved.
- School **name** centered, bold, scaled to fit at 375 px viewport.
- Address line (if `institutions.address` is set) — small, muted, single line; collapses gracefully if null.
- 1 px teal (`var(--brand-primary)`) accent rule under the name.
- Meta-strip — single line of pipe-or-dot-separated facts: `Class · Subject · Title · Date | Duration · Total Marks · Pass`. Replaces the 3×2 grey tile grid.
- Title + description below the meta-strip, centered.

If `logo_url` is null: header collapses to "School Name centered + accent rule" — no broken-image icon, no placeholder square.

## Data plumbing

**New hook:** `src/hooks/useInstitutionBranding.ts`

```ts
useInstitutionBranding(institutionId?: string | null): {
  branding: {
    id: string;
    name: string;
    address: string | null;
    contactEmail: string | null;
    contactPhone: string | null;
    logoUrl: string | null;
  } | null;
  isLoading: boolean;
}
```

Behavior:
- If `institutionId` is provided, fetches `institutions` row for that id.
- If omitted, falls back to current user's `profiles.institution_id` (same chain `AppLayout`'s `header-institution` query uses).
- Never throws — returns `{ branding: null }` on any failure.
- 5-minute `staleTime` (logos / addresses change rarely).
- Query key: `["institution-branding", institutionId ?? "current", userId]` — invalidated alongside the existing `header-institution` key by `useUploadInstitutionLogo`.

## Shared paper render

**New files** (under `src/components/exam/paper/`):

| File | Responsibility |
|---|---|
| `types.ts` | `ExamPaperData` normalized shape (institution + exam meta + sections + questions). One shape consumed by both screen render and HTML builder. |
| `normalizeExamPaperData.ts` | Two converters: `fromExamFormData(formData, stats, branding, contextLabels?)` (editor surfaces) and `fromFetchedExam(row, sections, branding)` (DB-backed surfaces). |
| `ExamPaperDocument.tsx` | Pure React render of the letterhead + meta-strip + sections + questions + footer. Accepts `ExamPaperData`. Uses `<MathText>` so on-screen preview renders LaTeX. Used by all four Tier-1 surfaces for the in-dialog preview. |
| `buildExamPaperHtml.ts` | Pure function `ExamPaperData → string`. Embeds the logo as a data: URL (caller pre-loads via `loadImageAsDataUrl`). Inline-styled, no Tailwind classes — for `window.open(...).document.write(...)` and for `html2pdf` fallback content. Math is left as raw `$...$` (same limitation as today, surfaced as a known issue but not in scope to fix). |
| `printExamPaper.ts` | `(html: string, filename: string) => void`. Wraps the popup-blocker handling + onload print + close. |
| `loadLogoDataUrl.ts` | Reuses the same `loadImageAsDataUrl` helper that `src/lib/pdf/studentReport.ts` already exports. New thin wrapper that caches by URL in a module-level `Map` so the same logo isn't re-fetched four times in a session. |

The HTML builder owns one source of truth for the print stylesheet. Today's four inline `<style>` blocks (one per file) collapse into one.

## Wiring (per surface)

For each Tier-1 surface:
1. Resolve `institutionId` (DB-fetched surfaces: from exam row; editor surfaces: omit → falls back to current user).
2. Call `useInstitutionBranding`.
3. Render preview with `<ExamPaperDocument data={normalized} />`.
4. Print button → `printExamPaper(buildExamPaperHtml(data), filename)`.
5. Download button (where applicable) → `html2pdf` over the rendered DOM node.

For Tier-2 results PDFs (`ExamReportPDF`, `StudentReportPDF`):
- A small helper `buildResultsLetterheadHtml(branding, examTitle, reportLabel)` returns just the header strip. Prepended to the existing HTML template. The rest of the template is unchanged.

## "Don't break anything" guardrails

- No DB schema changes (`institutions` already has every field we need).
- No RLS changes.
- No new runtime dependencies — `jspdf`, `html2pdf.js` already in `package.json`.
- All existing function signatures on the four Tier-1 surfaces are preserved — call sites in `ExamsPage`, `ReviewPublishScreen`, etc. do not change.
- KaTeX math: on-screen preview keeps rendering (via `<MathText>`). HTML/PDF print keeps showing raw `$...$` — same behavior as today, called out as a known follow-up.
- The current `html2pdf` paths (`DownloadQuestionPaperButton`, `OfflinePublishDialog`, `ExamReportPDF`, `StudentReportPDF`) keep their existing bitmap PDF mechanism. Vector-PDF upgrade is a separate spec.
- The "Generated by SALCI Assessment Platform" footer is removed, replaced with the school's contact line (phone/email if set) or a neutral "End of Question Paper" — the school is the publisher, not SALCI.
- If `useInstitutionBranding` returns null (e.g. super-admin previewing without a school context), all four surfaces fall back to a neutral header with just the exam title — no crash, no missing-data badge.
