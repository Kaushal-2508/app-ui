# Homework & Assignment Module

Merged to main 2026-06-02 (Phases 1–7, merge c2f349f), refined 2026-06-04/05 (R0–R6: locked pre-window preview, hard close at due, auto-check, publish gate, offline marks, non-submitter marks, multiple subjects). 8 tables + 7 RPCs + 2 pg_cron jobs + 1 private bucket + 3 edge functions + 6 lazy routes, gated by the `homework` institution feature flag (default-on, backfilled).

## Schema (migrations `20260601090000` … `20260605120000`)

* **homework_assignments** — `subject_id → universal_subjects ON DELETE RESTRICT` (subject hard-delete raises 23503, pre-translated in `useDeleteSchoolSubject`); `status` in draft/published/checked; `carries_marks` + `max_marks`; `visible_from` / `due_at` (CHECK due > visible); `offline_marks`; `academic_year TEXT NOT NULL`; single teacher attachment columns.
* **homework_assignment_classes** + **homework_assignment_subjects** (junction holds the FULL subject set incl. primary; `subject_id` stays the PRIMARY = `subjectIds[0]`; readers fall back to primary when junction empty).
* **homework_submissions** — UNIQUE(hw, student) = one-shot; `is_late` now always false (hard close).
* **homework_submission_files** — ≤10 per submission (trigger).
* **homework_results** — canonical identity UNIQUE(homework_assignment_id, student_id); `submission_id` nullable UNIQUE; status pending/graded/skipped.
* **homework_mark_audit** — trigger-written only. **homework_notifications_sent** — service-role only, claim table.
* RLS flows through 3 SECURITY DEFINER helpers: `can_manage_homework` (creator/admin/wing coordinator via `is_coordinator_for_class`/subject-matching teacher — keys off the PRIMARY subject only), `homework_visible_to_student`, `homework_open_for_submission`. Never inline their EXISTS bodies into policies (§23 recursion class).
* Students SELECT their `homework_results` row ONLY when assignment status = 'checked' — publishing is what reveals marks.

## Hard-won invariants

1. **`homework_marking_roster` columns must stay `::text`-cast.** `profiles.roll_number` is varchar(50); without `::text` the RPC raises 42804 at runtime, erroring 100% of calls — the marking page showed "0/0 submitted" with real submissions (fix: 20260602130000). Any `CREATE OR REPLACE` must keep all casts (`full_name`, `roll_number`, class `name`/`section`, result `status`/`feedback`). New homework RPCs should return **jsonb** instead (like `homework_student_feed`) to avoid the trap entirely.
2. **Error-before-empty on the marking page.** `HomeworkMarkingPage.tsx` renders an explicit error branch (`asn.isError || roster.isError` → EmptyState + Retry) BEFORE data branches. Pre-fix, RPC failures rendered "No submissions yet", masking the 42804 bug for a day. Every homework list surface needs the same discipline.
3. **`SubmissionFileViewer.getUrl` must be referentially stable.** Its thumbnail effect depends on `[file, getUrl]` and calls getUrl. Passing a useMutation's `mutateAsync` (identity changes per call) caused the "Maximum update depth exceeded" crash (9321c3e). Use `useHomeworkFileUrlResolver()` (empty-dep useCallback); `useHomeworkFileUrl` (mutation) is for one-shot click handlers ONLY.
4. **Regen `src/integrations/supabase/types.ts` from prod after any merge touching it.** The c2f349f auto-merge silently dropped 206 lines of homework types (restored in 393f329 via `npx supabase gen types typescript --project-id gyymkgohcijeksmrzuyw`).
5. **Asymmetric time windows are intentional.** Read (`homework_visible_to_student`) has only the LOWER bound — past-due stays readable. Write (`homework_open_for_submission`) adds `now() <= due_at AND offline_marks = false` and backs the INSERT policy, so direct PostgREST calls can't submit late/offline. Don't "tidy" the read helper by adding the due bound — closed homework would vanish for students.
6. **Locked pre-window teasers are nulled SERVER-side.** `homework_student_feed()` returns pre-`visible_from` rows with `locked: true` and description/attachment fields nulled in SQL. Don't reintroduce client-side `visible_from` filtering or client-side nulling.
7. **Two marking write paths, different identities.** Submitted students → `useUpsertHomeworkResult` upsert `onConflict: "submission_id"`. Offline + non-submitters → `homework_upsert_roster_marks` RPC, ON CONFLICT (assignment, student), COALESCEs existing submission_id. The roster RPC joins results by (assignment, student) — reverting to a submission_id join hides every offline/non-submitter mark.
8. **Publish gate R4 is authoritative in `homework_publish_marks`** (UI check is a mirror): future-due requires all submitted; all submissions graded/skipped. `carries_marks=false` skips gates and is ALSO auto-flipped to 'checked' by the `homework_auto_check_pass()` cron (`homework-autocheck-15min`). `offline_marks=true` skips both (OfflineMarkingView's "You missed N students" confirm covers completeness).
9. **An empty/invalid mark must never produce status='graded'.** `markError()` guard in HomeworkMarkingPage rejects empty/NaN/negative/over-max before commit — otherwise unmarked submissions would satisfy the publish gate.
10. **Edit-lock is a DB trigger** (`homework_enforce_edit_lock` + `homework_guard_class_changes`): content/class changes blocked once published AND visible. Status transitions stay writable. `useUpdateHomework` uses `.select("id")` + rowcount check so a blocked update errors instead of fake-succeeding; `useSaveHomework` re-verifies a draft is still 'draft' before updating.
11. **File-type allowlist lives in FOUR synced places:** bucket `allowed_mime_types` (20260601090100), `ALLOWED_MIMES` in submit-homework, `HOMEWORK_FILE_ALLOWED_MIMES` in `src/lib/fileValidation.ts`, `ALLOWED_MIME`+`BLOCKED_EXT` in HomeworkCreationFlow. Same 17 mimes (images/pdf/office/odf/text; NO video/audio/archives). Update all four together.
12. **Storage objects are owner-only.** Students sign their own files directly; teachers/markers MUST use the `homework-file-url` edge fn (service-role signs after `can_manage_homework`, TTL 300s). Don't widen the bucket SELECT policy. Upload path contract: clients TUS-upload to `${institutionId}/submissions/${homeworkId}/${studentId}/${uuid}-${safeName}` FIRST, then call `submit-homework`, which validates the prefix, verifies files exist in storage, and compensating-deletes the submission if file rows fail. Changing the client path format without the edge fn bricks submissions with 403.
13. **Notification idempotency = claim-first upsert** into `homework_notifications_sent` (ignoreDuplicates) before notifying; 2-day lookback windows; web-push rides `send-web-push` via `WEBHOOK_SECRET` (absent → in-app only, push silently no-ops). New notification types need the CHECK constraint + claim pattern.
14. **Teacher list tabs are computed** (scheduled = published & due>now; "submitted" tab = published & due<=now, badge "Closed"; checked) — no stored tab column. Drafts are a separate query.
15. **Feature flag gates nav, not routes.** FEATURE_URL_MAP covers /homework, /homework/create, /student/homework; CoordinatorDashboard's tile is HAND-wrapped in `isFeatureEnabled("homework")` (hand-rolled tiles outside NavigationHub need manual gates).
16. **Delete non-drafts via the `homework_delete` RPC, never a direct `.delete()`.** The `hw_assignments delete draft` RLS policy only allows `status='draft'`; a direct PostgREST delete on a published/checked row is silently RLS-blocked (looks like success, §6). `homework_delete(_homework_id)` (SECURITY DEFINER, `can_manage_homework`-gated, migration 20260605130000) removes ANY status; all child FKs are ON DELETE CASCADE, so one statement drops classes/subjects/submissions/files/results/audit/notifications. `useDeleteHomework` (RPC) backs the list-row "Delete" + destructive confirm; `useDeleteHomeworkDraft` (direct delete, RLS-allowed) stays for the drafts strip. STORAGE GAP: submitted bucket files are NOT FKed → orphaned on delete (needs a service-role cleanup pass; tracked follow-up).
17. **`useHomeworkScope` follows the active view-role for dual teacher+coordinator users.** A user holding both roles used to always get `isCoordinatorScope` (static `roleInfo.isCoordinator` check), so the Class(es)/Subject(s) picker showed wing classes even in teacher mode. Now gated on `activeViewRole` from `ActiveRoleContext` (the Teacher/Coordinator `RoleSwitcher` toggle, persisted in localStorage) when `hasDualRole` is true; single-role users and admins (`isSchoolAdmin`/`isSuperAdmin`) are unaffected. If a new homework surface needs role-scoped classes, follow this same `hasDualRole ? activeViewRole === X : roleInfo.isX` pattern — don't reintroduce a static-only check.
18. **`HomeworkMarkingPage`'s sticky footer must use `sticky bottom-0` + `-mx-4 sm:-mx-6 lg:-mx-10 xl:-mx-14` (cancelling `PageShell`'s content padding), NEVER `fixed inset-x-0`.** `fixed inset-x-0` positions relative to the viewport, so its frosted background spans edge-to-edge and bleeds over the left sidebar (a live bug, fixed for BOTH the online-marks and offline-marks footers — the offline one was missed in the first pass and had to be fixed separately). Mirrors `HomeworkCreationFlow`'s footer, which already shipped this pattern without incident. `PageHeader` on this page carries a `primaryAction` "View assignment" (opens a read-only `AssignmentViewSheet` with description/dates/attachment) — kept as `primaryAction` (solid, always-visible), not `secondaryActions` (ghost, hidden behind the mobile kebab), because it's the page's only other action besides the footer's Publish/Submit button.

## Known watch-items

* `homework_student_feed` may have LOST `offline_marks` in its jsonb: 20260605120000 (multiple subjects) redefined the feed from an older body without the key 20260604140000 added. Frontend reads `row.offline_marks` (falsy when missing → offline pill disappears, upload CTA shows; security still holds server-side). **Verify `pg_get_functiondef('public.homework_student_feed()'::regprocedure)` on prod before relying on the feed shape — re-add the key if missing.**
* `can_manage_homework` does not cover SECONDARY subjects (multiple-subjects feature) — a teacher matching only a secondary subject gets no manage rights unless `ca.subject_id IS NULL`. Design note, possibly intentional.
* The notify cron embeds the anon JWT literally in 20260601095000 — anon key rotation requires re-scheduling it (same pattern as send-task-notifications).
* `supabase/functions/homework-file-url/index.ts` checks attachment existence (404 "No attachment.") BEFORE the `can_manage_homework`/`homework_visible_to_student` authorization gate — an unauthorized caller with any valid `homework_assignment_id` can distinguish 404-vs-403 to learn whether an assignment exists and has an attachment (minor info-disclosure oracle; not exploitable beyond that). Fix = move the auth check ahead of the attachment_path lookup. Not yet fixed (found 2026-06-06 review, out of scope for that task).
* `MobileSheet`'s `Content` is a hardcoded `bg-white` (no `.dark` token override) — every sheet built on it (including `AssignmentViewSheet`) shows `ink-*` text (which flips to a light-mode scale in dark mode) on a forced-white background, i.e. low-contrast in dark mode. Pre-existing across ALL `MobileSheet` usages, not introduced by any one sheet. Real fix belongs in the shared primitive (`src/components/shared/sheets/MobileSheet.tsx`): swap `bg-white` for a token-backed surface with a `.dark` override.
