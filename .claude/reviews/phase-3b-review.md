## Phase 3b Code Review — olympiad/phase-1

### §5a Contract Sweep

Note: §5a requires running `npx tsc --noEmit`, `npx eslint`, and `npx vite build` directly. These are shell commands that cannot be executed by this read-only reviewer agent. Exit codes must be verified by the developer. The review below is based entirely on static file analysis.

---

## Summary

Phase 3b is architecturally sound and well-structured, with correct role separation, consistent design system usage, and proper `toastError` routing throughout. Three issues require attention before merge: unhandled errors on the DB writes inside `oly-lock-batch-schedule`, a PIN leak path via `useOlympiadBatches` being accessible to coordinator-role users in the routing, and a timezone ambiguity in the batch schedule generator.

## Issues

- **[severity: high]** Error handling / Correctness — `oly-lock-batch-schedule/index.ts` lines 78-80: The `delete()` and `insert()` calls for `oly_batch_assignments` do not check their return `error`. If the delete or insert fails (e.g. a constraint violation, RLS denial, or network error), the function silently continues, returns a 200 with `batch_ids`, and the school status is flipped to `batches_scheduled` with no students actually assigned to the batch. The batch exists in the DB with zero assignments and no error is surfaced to the caller. Fix: destructure `{ error }` from both calls and return a 500 if either is set, before advancing to the next batch in the loop.

- **[severity: high]** Security — `useOlympiadBatches` (`src/hooks/olympiad/useOlympiadBatches.ts`) queries `oly_batches` directly and includes the `pin` column in its select list (line 31). This hook is used by `OlympiadSchoolBatchesPage` and `OlympiadSchoolPinCustodyPage` — both school_admin-only pages. However, the `/school/olympiad/batches` and `/school/olympiad/pin-custody` routes in `App.tsx` (lines 752-771) include `coordinator` in `allowedRoles`, and the sidebar for coordinator role does not surface these routes. The coordinator role is present in `allowedRoles` on all three Phase 3b school routes, so a coordinator who navigates directly to `/school/olympiad/pin-custody` would load `useOlympiadBatches` and receive raw PINs from the DB (assuming RLS permits it). If the `oly_batches` RLS policy grants coordinators read access, PINs are exposed. Verify RLS on `oly_batches` restricts PIN visibility to `school_admin`/`super_school_admin` only, or remove `coordinator` from the `allowedRoles` on the pin-custody and batches routes.

- **[severity: important]** Correctness — `oly-generate-batch-schedule/index.ts` line 77: `cursor` is initialized as `new Date(\`${input.date_from}T${input.day_start_hh_mm}:00\`)`. When this runs in a Deno edge function (UTC runtime), a date string without timezone offset (e.g. `"2026-06-01T09:00:00"`) is parsed as **local time by the JS spec** — but Deno's V8 treats bare ISO strings as UTC, making `"2026-06-01T09:00:00"` parse identically to `"2026-06-01T09:00:00Z"`. The batch `scheduled_at` values are therefore stored as UTC 09:00, which is 14:30 IST. For a school that sets `day_start_hh_mm: "09:00"` expecting IST 9am, all batches are scheduled 5.5 hours late in wall-clock terms. The current code produces the correct `scheduled_at` string only by accident if the caller pre-converts to UTC — but the input spec (a bare `HH:MM`) gives no indication this is required. Fix: either document that all time inputs must be UTC, or accept a timezone parameter and convert explicitly using `Intl.DateTimeFormat` or a tzdata offset before constructing the `Date`.

- **[severity: important]** Correctness — `BatchKanban.tsx` drag-end handler (lines 58-62): When the user drops a card into an empty slot (i.e. a slot that previously had items but is now empty due to prior drags), `slots.get(k)?.some((b) => b._id === overId)` may not find the `overId` in any slot — because the `slots` Map is computed from `draftBatches` **before** the mutation, but `over.id` could be the slot column header itself (the `key={k}` div) rather than a batch card `_id`. In practice `@dnd-kit/core` with `closestCenter` collision detection resolves `over.id` to the **nearest sortable item ID**, not a container ID, so dropping into a truly empty column returns `over = null` and the early return on line 47 handles it cleanly. This is safe given the current implementation, but the code comment "Recompute scheduled_at based on the target item's slot" is misleading — it actually resolves to the source slot if no matching batch is found (line 63 returns `null`, `newSlotKey` is null, `moved.scheduled_at` is unchanged). This means cross-column drops where the target card belongs to the same slot as the source card will not update `scheduled_at`. This is a minor correctness gap for mixed-grade same-slot batches, not a crash.

- **[severity: important]** Correctness — `useOlympiadBatches.ts` lines 40-47: The second query fetches all assignment rows for all batch IDs with `.in("oly_batch_id", ids)`. For a school with many batches this could easily return hundreds to thousands of rows with no `range()` pagination. Per §23.1, Supabase silently caps PostgREST reads at 1000 rows. If a school has more than 1000 student-batch assignment rows, `enrolled_count` will be under-counted without any error or warning. Fix: use a server-side RPC that returns `COUNT(*)` per batch, or at minimum add a `.limit(5000)` with a comment acknowledging the cap.

- **[severity: low]** Design system — `OlympiadSchoolAbsenteesPage.tsx` lines 206-225: The student selection checkboxes inside the MobileSheet are hand-rolled (`<button>` with a custom SVG checkmark div). Per §20b rule 9 and the shadcn-exclusive rule in CLAUDE.md §UI/UX Rules, form controls should use shadcn primitives. A shadcn `<Checkbox>` + `<label>` pair is the correct pattern here. The current implementation works but diverges from the design system and will not inherit future shadcn styling/theme changes.

- **[severity: low]** Correctness — `useOlympiadAbsenteesPool.ts` line 35: The PostgREST join `oly_batches!oly_batch_id(status)` returns `T | T[]` depending on the FK cardinality. The code handles this correctly with the `Array.isArray` guard on line 36. However, if a student has **multiple** assignments (e.g. was previously assigned to a cancelled batch and then a new batch), `assignedByStudent.set(...)` will be called multiple times for the same `oly_student_id`, with the last entry winning. The student will be shown as an absentee only if their **last-processed** assignment status is cancelled — not the most recent by date. Since `oly_batch_assignments` should have a `UNIQUE(oly_student_id)` constraint (enforced by the lock function's delete-before-insert pattern), multiple rows should not exist in practice. But if the constraint is absent or the delete failed silently (see high-severity issue above), this produces incorrect absentee classification.

- **[severity: low]** UX — `OlympiadSchoolAbsenteesPage.tsx` line 63: The `batch_label` uses an em dash (`—`) in the string `\`Absentees — ${...}\``. CLAUDE.md prohibits em-dashes in user-facing copy. Use a regular hyphen or the word "Absentees for" instead. Same issue appears in `oly-generate-batch-schedule/index.ts` line 111 (`\`${chunk[0].class_label} — Batch ${batchIdx}\``).

## Verdict

NEEDS CHANGES — the two high-severity issues (silent assignment insert failure in the edge function, and potential PIN exposure via coordinator role on `oly_batches` direct query) must be fixed before this ships to production. The timezone ambiguity in schedule generation is also a real data-correctness bug for IST schools. Low-severity items can be addressed in a follow-up.
