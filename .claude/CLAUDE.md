## 2. The 4-Layer Build Pattern
Execute features in this exact sequence:
1. **DATABASE** - migrations in `supabase/migrations/`; enforce `institution_id` FKs; RLS via `auth.uid()` + `has_role()`.
2. **EDGE FUNCTIONS** - Deno in `supabase/functions/`; 3rd-party APIs (OpenAI, Resend, Razorpay).
3. **FRONTEND** - pages in `src/pages/`, components in `src/components/` by role, `useQuery`/`useMutation` hooks.
4. **INTEGRATION** - feature gating (`useInstitutionFeatures`), audit logging, notifications.

**Ship order matters:** a migration that DROPs or narrows a column must not land before the frontend that stops reading it. Dropping `reported_issues.admin_notes` ahead of the deploy broke the live ticket UI (2026-08-31) and had to be re-added empty.

## 6. Error Handling - translate, don't leak
* **Error state renders BEFORE the empty state.** A failed query resolving as "zero rows" is this repo's single most common defect (73 teacher surfaces swept 2026-08-26, 5 broken). Never write `const { data } = useQuery(...)` without handling `error` - and the error state must cover stat tiles and headers, not just the list.
* **Every `onError` / `catch`-toast routes through `toastError(err, { fallback, context })`** from [src/lib/toast.ts](../src/lib/toast.ts) (§19). Never `toast.error(error.message)`.
* Empty result where rows are expected = likely RLS violation; check `institution_id` context.
* **A PostgREST DELETE blocked by RLS looks identical to success** (empty data, no error). For permission-sensitive deletes, re-SELECT by id and treat "row gone" as the only success signal (pattern: `useDeleteSchoolSubject`).
* Protect feature-gated routes with `ProtectedRoute`.

## 8. AI Question Generation - core invariants (full detail: `salci-module-notes` §8)
* **Difficulty defaults to 5, with an OPT-IN override** (changed 2026-09-11 on Tushar's instruction; it was hardcoded to 5 before, and older docs still say "no difficulty selector" - they are wrong). [AIGenerateQuestions.tsx](../src/components/exam/questions/AIGenerateQuestions.tsx) + [DifficultyChip.tsx](../src/components/exam-creation/components/DifficultyChip.tsx) give every chapter/topic row a band chip, and rows of 2+ a per-question expander. Bands map onto the existing 1..5 scale: **Easy 2, Medium 3, Hard 5**; `DEFAULT_DIFFICULTY_LEVEL = 5`, so an untouched row sends the same payload as before and the product line "always hardest, calibrated to grade level" still holds by default. Generation fans out ONE request per distinct level in a row. **Never remove the default, never let a band reach the edge fn outside 1..5, and keep the early-years server-side clamp** (Class 1 and below) - it is the only thing protecting Nursery from level-5 prompts.
* **Prod model `gpt-5-mini` at `medium` reasoning effort** (secrets `OPENAI_MODEL` + `OPENAI_REASONING_EFFORT`). **NEVER set effort to `low`** - hand-verified to produce mathematically wrong MCQs. Subject-based cost routing sends only Maths + science-family subjects to the reasoning model; others use `OPENAI_MODEL_BASIC`; `REASONING_SCIENCE_EXCLUDE_INSTITUTIONS` opts an institution out. Keep OpenAI billing auto-recharge on (the original org ran out of credits → platform-wide 429).
* **Grade MUST reach the prompt.** The chapter path once built a synthetic topic with no grade join, so every generation said `Grade Level: General` + difficulty 5 and Nursery "Letter B" produced persuasive-letter-writing questions. Grade resolves from `chapterId` (`syllabus_topics.grade_level_id`) with `classId` as fallback. **Class 1 and below** clamp to difficulty 2/3, get an early-years rule block, and bypass the reasoning model (`needsReasoning && !isEarlyYears`). Pre-primary `grade_number`s are NEGATIVE (Pre Nursery -4 … UKG -1/0). Never strip grade from the request bodies.
* **KaTeX delimiters are MANDATORY** (`$...$` / `$$...$$`) - plain-text math is a hard fail. Renderers: `MathText` (student-facing), `MathPreview` (author-only). Manual entry uses the MathLive builder.
* **`repairLatexEscapes()` before `JSON.parse`** - don't bypass (`\f` → form-feed destroys LaTeX irrecoverably). The control-letter repair is allowlist-based (`\nhave` vs `\neq`).
* **Keep the LLM under-delivery auto top-up and the single-flight add guard** (`isAddingRef` + slice-clamp + close-sheet-early) - removing either re-opens short-count / duplicate-question bugs.
* **Deploy:** `npx supabase@latest functions deploy generate-questions --project-ref gyymkgohcijeksmrzuyw` after any prompt/logic edit.

## 9. Generated columns - `final_results.percentage`
`NUMERIC(5,2) GENERATED ALWAYS AS (...) STORED`. Including `percentage` in INSERT/UPSERT raises `cannot insert a non-DEFAULT value` and the row is NOT written. **Never include it**; **never swallow a `final_results` write error** with `console.error` - always `throw` (the 2026-04-17 invisible-results bug was a success toast over zero inserted rows). Same rule for any computed column: check the migration DDL before writing.

## 9a. Destructive writes go through RPCs ONLY (detail: `salci-module-notes` §3, `prod-operations`)
Client code must never DELETE-then-INSERT a relationship table. On 2026-08-07 that pattern silently wiped two Alliance teachers' entire portals with no audit trail. Use the transactional helpers instead: `setStaffClassAssignments` / `setClassTeachers` ([src/lib/staffAssignments.ts](../src/lib/staffAssignments.ts)), `deleteInstitutionSubject` / `unassignSubjectFromClass` ([src/lib/subjectAdmin.ts](../src/lib/subjectAdmin.ts)), `set_student_class`, `review_student_leave`, `review_staff_leave`, `record_syllabus_progress`, `create_task_group`, `post_support_message`, `_support_apply_status`. They diff in one transaction, name blockers before writing, and audit-log the delta (`class_assignment_deletions` has no FKs so it survives cascades). **Any save that removes existing rows MUST confirm first, naming what it will remove.** Two or more dependent writes = ONE RPC, never sequential client calls.

## 21. User Deletion - Cascade Contract
Profile deletion → `admin-operations` edge fn → `auth.admin.deleteUser` → cascade chain `auth.users → profiles → every FK to profiles(id)` (migration [20260427120000](../supabase/migrations/20260427120000_fix_user_delete_cascade.sql)). **CASCADE** on ownership columns (`user_id`, `student_id`, `teacher_id`, `parent_id`, `assignee_id`, `participant_id`); **SET NULL** on authorship columns (`created_by`, `published_by`, `actor_id`, `uploaded_by`) so the row survives, author unknown. **Every new column referencing `profiles(id)` MUST declare `ON DELETE`** - never default `NO ACTION`, never `SET NULL` + `NOT NULL` (cascade writes NULL, NOT NULL raises, the whole delete aborts).

**The cascade goes deeper than the FKs on the user, and it broke three times** (2026-04-22, 09-11, 09-25; GoTrue only ever says "Database error deleting user"). Two things abort it that no FK-on-profiles sweep can see: **(1) a guard trigger** - `ON DELETE SET NULL` runs as an UPDATE, so every BEFORE UPDATE guard on the child fires; `prevent_finalized_changes` made 47 teachers undeletable. A guard that can RAISE on such an UPDATE must first return early on `is_user_delete_cascade_update(TG_RELID, to_jsonb(OLD), to_jsonb(NEW))`, the one shared predicate. **(2) an FK hops down** (`ocr_extractions.attempt_id` RESTRICT blocked students via attempts). Migration [20260925120000](../supabase/migrations/20260925120000_user_delete_cascade_part3.sql). **After any migration that adds a table, an FK or a guard trigger, run [probe-user-delete-blockers.sql](../scripts/probe-user-delete-blockers.sql) (catalog, instant) and [probe-user-deletes.sql](../scripts/probe-user-deletes.sql) (real delete of every account, rolled back, batches of 500).** Only `support_settings.owner_id` (team@salci.in) may block, on purpose. Since 2026-09-25 a failed `delete_user` calls `diagnose_user_delete` (service_role only, always rolled back), logs the real Postgres error, writes a `user_delete_blocked` audit row with it in `metadata.diagnosis`, and toasts a reason the admin can act on; add a friendly case in `explainDeleteFailure` for any new deliberate blocker.

**Edge-function invoke contract.** All `admin-operations` call-sites go through [invokeAdminOperation](../src/lib/invokeEdgeFunction.ts) - a direct authenticated fetch, because `supabase.functions.invoke` sends an empty Bearer token in this client setup and caused spurious 403s. It reads the token from the local session, sets `Authorization` + `apikey`, and throws any `{ error }` body as a real Error for `toastError`. ~31 files still call `functions.invoke` directly - migrate identity-dependent ones as drive-by cleanup.

* **Never call `supabase.auth.getUser()` without a JWT argument** - read from `useAuth` / local session. A containment monkey-patch in [client.ts](../src/integrations/supabase/client.ts) must NOT be removed (167 call sites), but new code must avoid the pattern.
* **No `select("*")`** outside admin tooling - explicit column lists.
* **Paginate every unbounded list** with `range()` (not `offset`) - PostgREST silently caps at 1000 rows, inside edge functions too. A WHERE filter is NOT a bound.
* **Aggregate server-side** (RPC, embedded `count()`, `{ count, head: true }`) - never fetch rows to `.length` them.
* **Every new FK gets an index in the same migration.** **RLS policies call SECURITY DEFINER helpers only** - never inline cross-table EXISTS (recursion trap) - and wrap stable per-row calls as `(select auth.uid())`.
* **React Query:** explicit `staleTime` (≥ 60_000 unless justified in a comment); `refetchInterval` < 30s forbidden without a justification comment (sanctioned: LiveProctoringPage 5s, useOfflineScan 5s); `refetchOnWindowFocus: false` for heavy tables; every subscribing `useEffect` cleans up. **Query data is persisted to localStorage across reloads** ([queryPersist.ts](../src/lib/queryPersist.ts), since 2026-09-17): only plain-JSON data is restored, a `Set`/`Map`/`Date` result starts empty and fetches (a Set restored as `{}` killed /school/attendance on 2026-09-18); bump `SNAPSHOT_VERSION` whenever a stored shape or encoding changes, `MAX_AGE_MS` does not flush bad data for a day. Guarded by `npm run test:cache` ([scripts/test-query-persist.mjs](../scripts/test-query-persist.mjs)), which round-trips real data through the persister; typecheck, lint and build cannot see this class of bug because the shape only changes on the way through storage.
* **Mutations are idempotent** - single-flight guard, upsert/`ON CONFLICT`, or a unique constraint handled gracefully.
* **Bundle:** < 500 KB/chunk, < 1.5 MB entry. Lazy-load every page route and heavy libs (XLSX, jsPDF, KaTeX, recharts, pdfjs, exceljs).
* **Realtime:** one channel per feature, never per component; prefer `refetchInterval: 60_000` over a new subscription. **Edge fns:** >10s work becomes a background job (enqueue → id → poll).
* **Infra floor:** Medium compute minimum (Large at 1K+, XL at 10K+), Supavisor transaction pooling, read replicas for analytics, Sentry, k6 scripts in `scripts/loadtest/`, rate limiting on expensive edge fns.

## 24. Institution-Local Timezone for ALL time comparisons (CRITICAL)

## 25. Teacher authority is SUBJECT-scoped (full detail: `teacher-authority-scope` skill)

## 26. Prod & DB operations (full detail: `prod-operations` skill)
`supabase_migrations.schema_migrations` is NOT maintained - apply prod SQL through the Management API (`scripts/run-sql.ps1`, PAT in Windows Credential Manager) and verify against `pg_proc` / `information_schema` / `pg_indexes`, never against the ledger. **New SECURITY DEFINER RPCs must `REVOKE ... FROM anon` BY NAME** (Supabase default privileges grant `EXECUTE` to `anon`; `REVOKE FROM PUBLIC` does NOT strip it) and be verified via `information_schema.routine_privileges`. **Every RLS UPDATE policy needs both `USING` and `WITH CHECK`** - a missing `WITH CHECK` silently rejected 100% of teachers' offline-marks saves for two days (2026-08-25). Views that gate on the caller must stay `security_invoker=on`. A unique INDEX is invisible to `pg_constraint`: check `pg_indexes` before concluding `ON CONFLICT` is impossible. **Never make a primary key out of FKs to two tables** (e.g. `(user_id, institution_id)`): PostgREST reads that table as a many-to-many junction and every embed between the two tables fails with PGRST201; `admissions_overrides` broke every profile-with-school page for 70 minutes on 2026-10-12. Use an `id` PK plus a UNIQUE. A policy may call only functions `authenticated` can EXECUTE, or every read of that table errors.
